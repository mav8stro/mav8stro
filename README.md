## 🧭 Chapter 4 — Inside E-Patient, The Flagship Quest

**E-Patient** is an **AI-assisted pre-consultation healthcare web portal** that aggregates doctors from multiple hospitals into a single platform — built to serve **patients, doctors, and hospital administrators** all at once.

```mermaid
flowchart TB
    subgraph UserLayer[User Layer]
        PAT[Patient]
        DOC[Doctor]

    subgraph CoreLayer[E-Patient Platform]
        UI[Web Portal]
        API[API Layer]
        AIENGINE[AI Pre-Consultation Engine]
        DB[(Aggregated Hospital Data)]
    end

    PAT --> UI
    DOC --> UI
    ADM --> UI
    UI --> API
    API --> AIENGINE
    API --> DB
    AIENGINE --> DB

    style DB fill:#00C853,stroke:#00C853,color:#000
```

**🎥 Demo:** *[Add a screen-recording GIF or a link to a live/video walkthrough of E-Patient here — GitHub READMEs don't autoplay video, so a short GIF thumbnail linking out works best.]*

**Why it matters:** healthcare access is fragmented across hospitals with their own separate systems. E-Patient's bet is that a single AI-assisted portal — one that pre-screens and routes patients intelligently before they ever sit down with a doctor — makes the whole system faster for everyone touching it.

## 🏆 Chapter 7 — Quest Log & Philosophy

```mermaid
flowchart LR
    IDEA(["💡 Idea"]) -->|Research| RES(["🔍 Research"])
    RES -->|Prototype| MVP(["🧪 MVP"])
    MVP -->|Build| DEV(["⚙️ Development"])
    DEV -->|Validate| TEST(["🧷 Testing"])
    TEST -->|Ship| DEPLOY(["🚀 Deployment"])
    DEPLOY -->|Learn| ITER(["🔁 Iteration"])
    ITER -->|Next Quest| IDEA

    style IDEA fill:#0F0C29,stroke:#00F7FF,color:#fff
    style RES fill:#1a1a4f,stroke:#00F7FF,color:#fff
    style MVP fill:#242b6f,stroke:#00F7FF,color:#fff
    style DEV fill:#204a5f,stroke:#00F7FF,color:#fff
    style TEST fill:#26596f,stroke:#00F7FF,color:#fff
    style DEPLOY fill:#00C853,stroke:#00C853,color:#000
    style ITER fill:#FF6B00,stroke:#FF6B00,color:#000
```

| Principle | Approach | Why It Matters |
|---|---|---|
| ⚡ **Build** | Turn ideas into working products fast | Speed reveals what actually matters |
| 🧠 **Learn** | Improve through real experimentation | Theory only goes so far |
| 🏗️ **Engineer** | Think in systems, not just features | Features rot; systems scale |
| 🔍 **Test** | Validate before scaling anything | Scaling the wrong thing is expensive |
| 🚀 **Iterate** | Never stop improving | Version 1 is a hypothesis, not a finish line |
| 🌍 **Impact** | Solve problems that actually matter | Impact is the only metric that compounds |
| 🤝 **Collaborate** | Build alongside others when it helps | Some quests are better as a party |
| 🔬 **Question** | Doubt the easy answer | The obvious fix often hides the real one |

## 🛠️ Chapter 10 — The Setup Lab (optional upgrades)

These aren't plug-and-play — each needs a small one-time setup on your side. Listed here so you know exactly what's live vs. what needs activation.

<details>
<summary><b>🐍 Snake contribution animation</b> — needs a GitHub Action in your profile repo</summary>

Create `.github/workflows/snake.yml` in your **`mav8stro/mav8stro`** repo:

```yaml
name: Generate Snake
on:
  schedule:
    - cron: "0 0 * * *"
  workflow_dispatch:
  push:
    branches: [ main ]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: Platane/snk@v3
        with:
          github_user_name: mav8stro
          outputs: dist/github-contribution-grid-snake-dark.svg?palette=github-dark
      - uses: crazy-max/ghaction-github-pages@v4
        with:
          target_branch: output
          build_dir: dist
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

</details>

<summary><b>🎧 Spotify "Now Playing" widget</b> — needs your own Spotify API auth</summary>
